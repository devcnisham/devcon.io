# devstep

A Developer Project Operating System — take a project from idea to production
in one place: understand it, plan it, build it, ship it, monitor it.

## Documentation

Start at [`docs/README.md`](docs/README.md) — product definition, architecture,
database plan, roadmap, feature workflow, and current build status.

## Stack

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **Tailwind CSS v4**
- **shadcn/ui** (Base UI, `base-nova` style, neutral base color)
- **lucide-react** icons, **next-themes** for dark mode
- **Zod** + **react-hook-form** for validation, **Vitest** for tests
- **argon2id** (`@node-rs/argon2`) for password hashing, `server-only` for the
  client/server boundary

## Structure

```
src/
  app/                  routes — (auth), (marketing), dashboard, projects,
                        workspaces, activity, settings, api
  middleware.ts         edge route guard
  components/
    ui/                 shadcn/ui components (generated — do not hand-edit)
    layout/             app shell: sidebar, topbar, theme toggle
  features/             one folder per domain — see src/features/README.md
    auth/  workspace/  project/  dashboard/  codebase/
    _template/          copy this to start a new feature
  config/               site.ts, nav.ts
  hooks/                shared React hooks
  lib/
    env.ts              validated environment variables
    utils.ts            `cn()` helper
  types/                shared types
docs/                   project documentation — start at docs/README.md
tests/                  shared fixtures and stubs
```

Unit tests live beside the code they cover (`lib/thing.ts` →
`lib/thing.test.ts`), so a feature stays self-contained.

## Current state

The UI, validation, and domain logic are built and tested — **250 passing
tests**. Nothing persists yet: there is no database, so creating a workspace or
a project reports that it cannot be saved. Local project import is the one flow
that works end to end, and its index is discarded.

## Conventions

- Import through the `@/*` alias, never relative paths across folders.
- Read environment variables via `@/lib/env`, never `process.env` directly.
- Feature-specific components, hooks, and types live in `src/features/<feature>/`
  and are imported through that feature's `index.ts`; only genuinely shared code
  goes in the top-level folders. See `src/features/README.md`.
- `src/components/ui/**` is generated by the shadcn CLI. Add components with
  `npx shadcn@latest add <name>`.

## Adding a route

Place it in the matching route group: `(marketing)` for public pages, `(auth)`
for sign-in flows. Route groups do not affect the URL.

Anything behind the app shell gets its own top-level folder with a `layout.tsx`
that wraps `<AppShell>` and calls `requireSession` — see
`src/app/dashboard/layout.tsx`. Add the route to `PROTECTED_PREFIXES` in
`src/features/auth/lib/route-policy.ts` so the middleware guards it too.
